### Automatically discovered screens

Put each full-screen presentation component in `src/screens/**/*.tsx` with a default export. Its filename becomes the display name, and its folders become the group. For example, `src/screens/cats/new-arrival.tsx` automatically appears as **Cats / New Arrival**, without a central registration list. Vite updates discovery when files are added or removed. Keep helper components in `src/components/` so they are not treated as screens. Load only the selected screen, rather than importing every screen during preview startup.

A screen requiring props, simulated data or extra states gets a matching sidecar, such as `src/screens/cats/new-arrival.preview.tsx`. It is discovered automatically and supplies the default fixture and optional state components:

```tsx
import NewArrival from './new-arrival'

function DefaultPreview() {
  return <NewArrival catName="Mochi"/>
}

export default {
  Default: DefaultPreview,
  cases: {
    'Empty name': () => <NewArrival catName=""/>,
  },
}
```

Without a sidecar, preview renders the screen's default export without props. Automatic discovery does not invent required props or business data: provide safe fixtures when needed. Keep service orchestration outside screen presentation, and never import Firebase, real account containers or production write operations into preview fixtures. Production code must not import `*.preview.tsx` or `src/dev/` modules. Tests inspect production chunk modules as well as output text to verify their exclusion.

### Startup updates and text selection

The startup gate in main.tsx runs before importing App or initializing account services. An ordinary document load checks version.json once, generated from package.json by the existing Vite plugin. The cache-bypassing request omits credentials, rejects redirects and aborts after five seconds. Concurrent checks share one promise. Missing, invalid, offline or timed-out metadata opens the current application. Returning to an already running document does not check again; there is no polling, focus/visibility refetch or database operation.

When a newer version exists, reuse PageLoading with Loading the latest version. Fetch the same-origin entry HTML with no-store and a ten-second timeout. Verify the application-version meta tag is at least the target before navigating with focuswilds-update and focuswilds-refresh query parameters. Preserve the path, other query parameters and hash, including OAuth callback state. The bootstrap HTML shows the same cat/message while React loads after navigation. No artwork or animation frames change.

On return, compare the actual bundled package version with the target marker. A matching or newer bundle opens the application and removes the two update parameters. An older bundle stops at Update unavailable; no automatic retry occurs. Try again performs another bounded HTML fetch/navigation. Continue with current version removes only the update markers and opens account restoration. This gate runs before any gameplay state exists and must stay at startup as future timers and drafts are implemented. The old inline update notice and its controller have been removed. Local preview offers Loading > Updating app and System > Update Error without account services or real update requests.

Request budget: one small static version.json per ordinary load (about 22 bytes, excluding headers); an outdated release adds one HTML preflight (about 4 kB), followed by a normal same-origin navigation and its asset requests. Explicit retries repeat the HTML request and navigation; they do not poll metadata. A marked return makes no additional metadata request. No database reads/writes, service worker or persistent update storage are added. Continue does not clear sign-in storage. Build metadata cannot guarantee bundle delivery or immediate CDN/OS icon refresh. Navigation can still repaint; a network loss after preflight or entry-bundle failure may use browser/general startup recovery rather than the update recovery. Previously deployed code gains this behavior only after it is refreshed.
