## GitHub Pages sign-in without popups (2026-10-19)

This supersedes the earlier popup preparation fix. Keep GitHub Pages and the existing Firebase project/owner UID. Start a same-window GitHub authorization using the public Firebase REST `accounts:createAuthUri` endpoint. Retain the returned session ID and state only in same-origin sessionStorage for at most 10 minutes. On return, consume and remove that challenge, validate state/callback/age, strip the one-use code from the address bar, and exchange it through `accounts:signInWithIdp` with `autoCreate: false`. Only an owner UID response can pass the returned GitHub credential to the Firebase SDK for persistent sign-in. Tokens are never logged or stored manually; Firebase manages its own persisted session. A no-referrer policy prevents callback query data leaking through referrers. No popup, cross-origin Auth iframe, password UI, new backend, Billing, database access or provider secret is added.

The REST exchanges attach App Check tokens; SDK credential sign-in and refresh retain App Check as well. A fresh login uses one createAuthUri request, one REST signInWithIdp exchange and one SDK credential sign-in (plus SDK account lookup/attestation as needed). Returning with an existing session skips OAuth calls; Firebase may still refresh/validate Auth tokens. No Firestore reads/writes, listeners or polling are introduced. Do not treat mocked tests as production acceptance.
